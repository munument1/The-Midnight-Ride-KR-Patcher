## 1. UFO4P 지몬자 번역 후 플레이 불가 제보

현재 배포물에서는 다음 네 레코드의 **헤더와 압축된 데이터까지 포함한 레코드 전체 바이트**가 원본과 같습니다.

| 종류 | 원본 파일 내 FormID | 식별 정보 |
|---|---|---|
| LCTN | `00055402` | `RelayTowerZimonjaLocation` |
| CELL | `0000DCEC` | `RelayOutpostZimonja` |
| REFR | `0002495A` | 지도 마커, FULL = `Outpost Zimonja` |
| REFR | `1004E64B` | `UFO4POutpostZimonjaFTMarker` |

`LCTN`의 FULL도 `Outpost Zimonja`로 남아 있습니다. 위 FormID는 이 버전 UFO4P 파일의 원시 ID이며, 게임 실행 시 표시되는 로드 순서 ID를 의미하지 않습니다.

백엔드는 Fallout4.esm 소유의 세 고정 ID와 EditorID에 `Zimonja`가 있는 레코드를 번역에서 제외합니다. 이를 direct/fallback 양쪽에서 검사하고, 독립 검증기도 마스터 인덱스를 해석하여 같은 정책을 확인하도록 보강했습니다. PPF와 PRP의 지몬자 CELL 전체 바이트도 원본과 같습니다.

장소명 번역이 과거 증상의 직접 원인이었는지는 이 검사로 확정할 수 없습니다. 현재 정책은 제보된 조건을 피하기 위한 예방 조치입니다.

## 2. 구형 번역 도구로 PRP 저장 후 지형 로딩 이상 제보

현재 패쳐는 Mutagen으로 재직렬화한 파일을 최종 payload로 사용하지 않습니다. 비교용 사본에서 승인된 표시 문자열 변경을 찾고 원본 바이너리에 해당 문자열만 반영합니다. 그 뒤 WRLD의 OFST·CLSZ와 그 필드에 속한 XXXX 확장 크기만 제거합니다. 저장된 오래된 오프셋을 그대로 재사용하지 않는 정책이며, 월드 인덱스를 재계산하는 방식은 아닙니다.

| 파일 | 레코드 수(TES4 포함) | 치환된 표시 필드 | 제거한 OFST / CLSZ | 남은 월드 인덱스 |
|---|---:|---:|---:|---:|
| UFO4P | 31,749 | 18,765 | 0 / 0 | 0 |
| PPF | 25,440 | 239 | 9 / 9 | 0 |
| PRP | 8,277 | 329 | 8 / 8 | 0 |

세 파일 모두 다음을 확인했습니다.

- 레코드 집합·순서, FormID, 마스터 목록과 순서가 보존됩니다.
- 레코드·GRUP 헤더는 길이 값 이외의 바이트가 보존됩니다.
- 표시 문자열은 실제 direct/fallback 사전의 원문·번역문 쌍과 일치합니다.
- 허용된 WRLD 인덱스 제거 외에는 비번역 필드의 헤더·내용·XXXX가 바이트 단위로 보존됩니다. 지형·배치·내비메시·프리컴바인/프리비즈 관련 비표시 데이터도 같은 검사 범위에 포함됩니다.
- 본문이 변경되지 않은 레코드는 압축된 바이트까지 원본과 같습니다.
- 파일/그룹 경계, 압축 해제 크기와 중복 레코드 여부를 검사합니다.

이는 원본 데이터 손상과 잔존 인덱스를 검사한 결과입니다. 과거 xTranslator 문제의 정확한 원인을 재현하거나, 인덱스 제거 후의 게임 성능·지형 표시를 보증한 결과는 아닙니다.

## 게임 내 확인이 남은 범위

영문 원본 상태와 번역 적용 상태를 같은 모드 순서·같은 복사 세이브로 비교해야 합니다. 지몬자 외곽에서 도보로 접근하고 경계를 왕복하며, 빠른 이동·실내외 전환·저장 후 불러오기를 확인합니다. 과거 지형 문제가 있었던 지점과 도심에서도 지형/건물 누락·깜빡임·충돌·NPC 이동·프레임 변화·CTD를 비교해야 합니다. 아직 이 게임 내 비교는 수행하지 않았습니다.

이미 이전 번역 도구로 덮어쓴 플러그인은 깨끗한 해당 버전 원본을 복원한 다음 새 Output을 생성해야 합니다. 새 패쳐가 기존 손상이나 이미 세이브에 기록된 상태를 자동 복구하지는 않습니다.
